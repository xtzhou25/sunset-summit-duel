# 固定虚拟摇杆：独立原生输入回归

## 最终结果

- `joystick_native_test.gd`：360 个断言，6 个布局，0 失败。布局为 568×267、844×337、375×614、390×791、960×600、1280×800。
- `joystick_gameplay_test.gd`：42 个断言，3 个角色，0 失败。运行实际 main/Combat，使用明确的静止对手夹具，不修改玩家高度、速度、动作时钟或命中状态。
- 原有 `feedback_preferences_test.gd`：486 检查通过；`qi_choice_input_test.gd`：990 检查通过；`spacing_scene_test.gd`：190 检查通过。

以上是断言数，不是同样数量的独立玩家操作场景；不同套件有覆盖重叠，不将其相加宣传为独立场景数。

## 输入覆盖

通过 `root.push_input` 注入真实 Godot `InputEventScreenTouch` / `InputEventScreenDrag` / 鼠标事件，而非直接调用方向计算函数。验证固定基座与可视 nub 几何、中心中立、八方向、初次进入和退出阈值迟滞、重复拖动保持上方向不重新跳、回中心后再次向上产生一次新边沿。

单 owner：第二根落在基座内的手指不能接管、合并反方向或在第一根松手后自动继承；攻击手指独立，五个攻击均可和方向同时输入。松开任意一侧不取消另一侧。方向手指拖到攻击按钮不能变攻击；攻击手指拖到摇杆不能变方向。外部开始的触点不能拖入获得方向。mouse 与 touch 互不抢占，鼠标丢失按键 mask 清空捕获。

owner 拖出基座继续方向并限制 nub 到半径内，这是当前明确的摇杆规则，不沿用旧方形方向区“拖出即中立”。基座位置不跟随手指漂移。释放、canceled、焦点丢失、暂停、菜单和尺寸重排都会清空捕获、归中；旧触点后续 drag 不能重新激活。

所有布局下基座及五个攻击目标在原保留区域内，目标至少 44 像素且不相互覆盖。不把这些逻辑和几何检查当成手机视觉或物理触摸认证。

## 真实游戏状态覆盖

三角色分别经视口触摸完成：直接斜向起跳、保持上方向在空中换向、落地后仍保持上不自动再跳、回中再向上才能再次起跳、按下蹲伏与松手站起。键盘方向与摇杆方向按来源合并，松开触点不抹掉仍按住的键盘。焦点丢失/暂停/返回菜单清空实际有效输入及 nub，新触点恢复正常。

输入释放的正确断言为所有 held 值为 false 且 taps 为空，而不是要求 held 字典物理为空：HUD 的释放信号可能在 main 清空后写入 false 条目。这是测试表达修正，未修改产品逻辑。

## 历史套件边界

`hud_test.gd` 的旧独立运行入口仍期待 P1 以前的 left/right/jump 独立按钮，行 124 访问已不存在的 `_touch_buttons.left` 后出现脚本错误；已终止，原日志保留，不记作通过。它作为部分其它测试的基类仍可使用公共辅助函数。没有修改或删除旧文件来掩盖错误。

`directional_hud_test.gd` 内的多指合并和拖出方向区归零期望属于旧方形方向区契约，本轮不把它当作有效摇杆验收入口。新的独立测试明确覆盖替代规则；保留旧文件作为历史记录。父工程负责其余完整战斗回归和发布检查。

原 `spacing_scene` 成功后存在历史 ObjectDB/resource 退出告警；保留日志，不声称所有历史日志零告警。新两套测试最终退出均为 0，无功能失败。
